## Embedding bridge

Started with `?host=parent` inside an iframe, WordCraft talks to its parent window with `postMessage`. It only accepts messages from the parent window on its own origin, and only sends to that origin. Every message is a plain object with a `type`:

| Message | Direction | Fields | Meaning |
|---|---|---|---|
| `wordcraft:ready` | WordCraft → parent | `version` | The app is listening; send a document now. |
| `wordcraft:open` | parent → WordCraft | `name`, `bytes` (`ArrayBuffer` or `Uint8Array`) | Open this document, as File › Open would. |
| `wordcraft:save` | WordCraft → parent | `name`, `saveAs` (boolean), `bytes` (transferred `ArrayBuffer`) | Every file WordCraft would otherwise download. Save sends the opened file's name with `saveAs: false`. Save As in a format that keeps everything (.docx and the other Word packages, .odt, .rtf), and a Save under a name the parent never sent (an imported .doc saved as .docx), send `saveAs: true`: the document is now that file, and the next Save sends its name with `false`. Exports and Save As in other formats (PDF, Markdown, plain text, a page as PNG) are copies, with `saveAs: false` and their own name. The parent stores the file and reports success or failure itself. |
| `wordcraft:dirty` | WordCraft → parent | `dirty` (boolean) | Unsaved changes appeared or went away. |
| `wordcraft:failed` | WordCraft → parent | `error` | The app couldn't start (for example, no WebGPU or WebGL2). |

With `?host=parent`, an optional `&author=<name>` signs the user's comments and tracked changes with that name for the visit (it isn't kept as the browser's own preference), and the parent (not WordCraft) guards leaving the page with unsaved changes.

Without `?host=parent`, WordCraft behaves exactly as upstream: Save and Export download the file.
